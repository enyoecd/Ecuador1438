# Botón de Cámara con Transmisión WebRTC — Ecuador 1438

## Contexto

Se integra un botón "Cámara" en la barra superior de `Puerta1.html` (entre "Regresar" y "Timbre") que permite iniciar una transmisión de video/audio en vivo usando **Cloudflare Calls SFU** (el producto es ahora llamado **Cloudflare Realtime SFU**). El estado de la sesión activa se controla en el **Cloudflare Worker existente** mediante **Cloudflare KV**, sin base de datos externa.

---

## User Review Required

> [!IMPORTANT]
> Esta implementación utiliza la **API REST de Cloudflare Calls SFU** directamente desde el Worker. Para que funcione necesitarás crear:
>
> 1. **Una aplicación Cloudflare Calls** en el dashboard (gratis hasta cierto volumen)
> 2. **Un Namespace de Cloudflare KV** para guardar el estado de la sesión activa (sin DB)
> 3. Dos **Secrets** en el Worker `puerta1-ecuador1438`: `CF_CALLS_APP_ID` y `CF_CALLS_APP_SECRET`
> 4. Un **binding de KV** llamado `CAMERA_STATE` en el Worker
>
> Se detallan los pasos exactos al final de este plan.

> [!WARNING]
> **Puerta2.html**: Por ahora se integra el botón solo en `Puerta1.html`, ya que el request lo especifica así. Si deseas aplicarlo también a Puerta 2, es un paso posterior simple.

## Arquitectura del Sistema

```
Visitante (Browser)
    │
    ├─ POST /  tipo=camara&accion=iniciar  ──► Worker (puerta1)
    │          <── { sessionId, token, appId } o { ocupado: true }
    │
    ├─ WebRTC (Cloudflare Calls SFU API) ◄──────────────────────┐
    │   usando sessionId + token                                  │
    │                                                             │
    └─ POST /  tipo=camara&accion=finalizar  ──► Worker (puerta1)
               <── { ok: true }

Worker (puerta1-ecuador1438)
    │
    ├─ KV CAMERA_STATE:
    │   key: "puerta1_camera"
    │   value: { sessionId, startedAt, expiresAt }
    │   TTL: 2 horas (auto-expire en KV)
    │
    └─ Cloudflare Calls API (REST)
        POST /sessions/new  →  crea sesión con credenciales
        DELETE /sessions/{id}  →  elimina sesión al finalizar
```

## Variables de Entorno y Configuración Requerida

### Paso 1: Crear Aplicación Cloudflare Calls

```
Dashboard Cloudflare → Realtime → Calls SFU → Create App
```
Anotar:
- **App ID** → `CF_CALLS_APP_ID`
- **App Secret** (token) → `CF_CALLS_APP_SECRET`

> **Alternativa (API)**:
> ```bash
> curl -X POST https://api.cloudflare.com/client/v4/accounts/{ACCOUNT_ID}/calls/apps \
>   -H "Authorization: Bearer {CF_API_TOKEN}" \
>   -H "Content-Type: application/json" \
>   -d '{"name":"Ecuador1438-Citofono"}'
> ```

### Paso 2: Crear Namespace KV

```
Dashboard → Workers & Pages → KV → Create namespace
Name: CAMERA_STATE_P1
```
Anotar el **Namespace ID**.

### Paso 3: Agregar binding KV al Worker

En `wrangler.toml` del Worker `puerta1-ecuador1438`:
```toml
[[kv_namespaces]]
binding = "CAMERA_STATE"
id = "EL_NAMESPACE_ID_ANOTADO"
```

O vía Dashboard: Worker → Settings → Variables → KV Namespace Bindings → `CAMERA_STATE`

### Paso 4: Agregar Secrets al Worker

```
Dashboard → Worker puerta1-ecuador1438 → Settings → Variables → Add Secret
```
- `CF_CALLS_APP_ID` = (el App ID del paso 1)
- `CF_CALLS_APP_SECRET` = (el App Secret del paso 1)

## Flujo WebRTC Detallado (Cliente)

```
1. Usuario toca "Cámara"
2. Browser solicita permiso cámara+micrófono
3. GET /estado → Worker verifica KV
   - Si ocupado: mostrar mensaje, no continuar
4. POST tipo=camara&accion=iniciar → Worker
   - Worker verifica KV (doble check anti-race)
   - Worker llama Cloudflare Calls API → crea sesión
   - Worker guarda {sessionId, token} en KV con TTL 2h
   - Worker devuelve {sessionId, token, appId} al browser
5. Browser crea RTCPeerConnection con TURN servers de Cloudflare
6. Browser crea offer SDP, envía a Cloudflare Calls API (directamente)
7. Cloudflare Calls devuelve answer SDP
8. Conexión WebRTC establecida → transmisión en vivo
9. Al finalizar: POST tipo=camara&accion=finalizar → Worker borra KV
```

## Viewer (observación remota — preparado para Telegram)

El Worker también expondrá un endpoint `tipo=camara&accion=ver` que devuelve:
- `sessionId` activo (si existe) + token de solo lectura para el viewer

Un futuro enlace de Telegram puede abrir `/viewer-p1.html?session=...` que:
- Conecta como viewer (solo recibe audio/video, también puede enviar para bidireccional)
- Usa el mismo `sessionId` del Worker KV

> [!NOTE]
> El archivo `viewer-p1.html` se crea en esta misma iteración como **preparación** para uso futuro desde Telegram. Funcional pero pendiente de integración con el bot de Telegram.

## Verificación

### Manual

1. Abrir `Puerta1.html` en el browser (localmente o en producción)
2. Verificar que aparecen tres botones: `[← Regresar]` `[📷 Cámara]` `[🔔 Timbre]`
3. Tocar Cámara → debe pedir permiso de cámara y micrófono
4. Si ya hay sesión activa → debe mostrar mensaje de ocupado
5. Worker devuelve session data → transmisión inicia
6. El botón queda deshabilitado mientras hay sesión
7. Tocar "Detener" → Worker libera KV → botón se reactiva

### Notas
- Sin el Worker actualizado y publicado, el botón mostrará error de red (esperado en local)
- Los estilos y UI del frontend son independientes del backend y se pueden verificar visualmente sin conexión al Worker
